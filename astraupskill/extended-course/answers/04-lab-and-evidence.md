# Answers: tests and capstone

The Python laboratory checks a limited ASCII fixture with numeric identifiers. It does not establish .NET comparison behavior for every Unicode title or Guid, nor does it run authorization and persistence. Its value is transparent arithmetic and meaningful mutations. Production unit tests and relational tests remain distinct evidence layers.

Changing the title weight should alter the five-point queue fixture. Removing query deduplication can make repeated terms increase score. Removing the ID tie-break allows input order to influence otherwise tied results. Making the threshold comparison strict excludes a document scoring exactly three. Each mutation corresponds to a stated contract property, so failures teach more than a broad snapshot mismatch.

The capstone screen should expose the log window, total evidence count, bounded sample and retrieval explanation. Its no-match state should direct manual investigation without fabricating a mitigation. The approval contract should identify the version reviewed and define stale-decision behavior. A newer run or edited document should not silently change the content authorized by an earlier click.

The claim/evidence matrix should mark historical tests as inspected evidence until rerun. Source inspection supports descriptions of control flow; a model supports its limited invariants; service tests support constructed records; relational tests support configured storage behavior; human labels support relevance evaluation. None alone establishes all the others. Full credit requires naming at least one remaining gap and a narrow next test.
